# Wiki ingest evidence — Task #33 (user_devices persistence)

## What changed
- Added PostgreSQL persistence model for push devices in Drizzle schema:
  - enum `device_platform` (ios|android|web)
  - table `user_devices`
  - unique indexes on `token` and `(user_id, token)`
- Added DB client (`services/api/src/db/client.ts`) using Drizzle + `pg`.
- Refactored `upsertUserDevice` in `services/api/src/store.ts` to use real DB queries when `DATABASE_URL` is set.
- Kept safe in-memory fallback when `DATABASE_URL` is absent (local non-blocking behavior).
- Updated `/users/me/devices` route to await async upsert.
- Generated migration assets via `drizzle-kit generate`:
  - `services/api/drizzle/0000_numerous_stature.sql`
  - `services/api/drizzle/meta/*`
- Marked Task #33 and subtasks as done in `.taskmaster/tasks/tasks.json`.

## Why it changed
- Device token storage in memory was volatile and lost on API restart.
- Production push requires durable storage in PostgreSQL.
