# Wiki ingest evidence — Tasks #34, #35, #36, #44, #45

## What changed
- Hardened API authentication to rely only on Supabase JWT validation:
  - Removed in-memory `dev_*` session bypass from `services/api/src/middleware/auth.ts`.
  - Reworked `services/api/src/routes/auth.ts` to Supabase-only signup/login/logout/me wrappers.
  - Removed local plaintext-password auth/session helpers from `services/api/src/store.ts`.
- Secured invite acceptance ownership:
  - `services/api/src/routes/invites.ts` now requires `requireAuth` and binds invite ownership to `c.get("auth").userId`, ignoring arbitrary body `userId`.
- Kept user profile compatibility after auth changes:
  - `services/api/src/routes/users.ts` now upserts/falls back from Supabase user data when local profile map is missing.
  - Added explicit public/admin Supabase client constructors in `services/api/src/lib/supabase.ts`.
- Updated vulnerable dependencies:
  - `apps/web/package.json`: `next` upgraded to `16.2.6`.
  - `services/api/package.json`: `drizzle-orm` upgraded to `^0.45.2` and `drizzle-kit` to `^0.31.10`.
- Marked Task Master items as done:
  - `.taskmaster/tasks/tasks.json`: tasks `34`, `35`, `36`, `44`, `45` set to `done`.

## Why it changed
- Eliminate plaintext password/session path and close auth bypass vector in production.
- Prevent invite token holder from linking an invite to arbitrary user IDs.
- Mitigate known dependency advisories (`next` critical chain, `drizzle-orm` SQL injection advisory).
